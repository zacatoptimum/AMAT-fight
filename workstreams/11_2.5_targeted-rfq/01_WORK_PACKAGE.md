# 2.5 定向提案／報價徵詢 — Work Package

## Purpose
把核准需求、market learning 與比較欄位轉成對所有 bidders 一致、可審計的 targeted RFQ / RFP process。
## Client question
如何取得可比較、足以進行 DD 與 shortlist 的供應方案，而不暴露不必要資訊或形成承諾？
## Intended decision
G6：核准 bidder list、package、assumptions、evaluation rules、Q&A / deadline與 launch authority。
## Client audience
Procurement owner、Sustainability、Finance、Legal、Facilities、decision body；external bidders。
## Optimum owner / supporting role
Procurement / Commercial Lead owner；Analyst manage Q&A / compliance；Project Lead QC；client Legal / Procurement approve instructions / disclosures。
## Inputs
1.5 / 1.6 approval、2.1–2.4 evidence、client requirements、NDA / security / procurement rules、evaluation methodology draft。
## Activities
lock assumptions → bidder instruction → mandatory fields / pricing template → briefing / Q&A → addenda → receive / log responses → compliance check。
## Outputs
`RFQ_RFP_PACKAGE.md/.docx`、`Supplier_Response_Template.xlsx`、`MODEL_README.md`、`BIDDER_BRIEFING_DECK_CONTENT.md`與精煉 briefing deck。
## Dependencies
輸出必須直接餵 2.6 Scorecard / DD；任何 material addendum 同步所有 eligible bidders。
## Known
Response comparability 需要相同 definitions、units、base dates、validity與evidence requirements；Optimum無權替client承諾award。
## Hypotheses
兩階段 process（compliance / clarification後才完整比較）可減少不完整 bids 造成的假精準。
## TBD with client
正式 process type、bidder list、identity disclosure、NDA、timeline、portal、currency / tax / base date、evaluation weights、award / reservation language。
## Key risks
不同假設導致不可比；Q&A不對稱；late change；價格與certificate / wheeling split不清；submission security；process challenge。
## MVP sequence
一頁 term / field list → one bidder-response demo → evaluator dry run → fix ambiguity → G6 launch → clarification round。
## Definition of Done
每個2.6 score / DD field都有supplier response / evidence欄；instructions、deadline、validity、Q&A / addendum、reservation of rights與confidentiality清楚；dry run無重大不可比欄位。

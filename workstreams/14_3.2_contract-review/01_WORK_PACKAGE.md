# 3.2 合約與交易條件審閱 — Work Package

## Purpose
用 commercial playbook辨識文件如何實現／偏離已核准交易，並把需法律解釋或法律風險意見的事項交給 qualified counsel。
## Client question
合約是否反映預期commercial deal、風險如何分配、哪些需談判／升級／法律意見？
## Intended decision
核准negotiation issue list、priority、owner、counsel questions與preferred / fallback commercial position。
## Client audience
Legal counsel、Procurement、Commercial / Finance、Sustainability、Facilities、decision approvers。
## Optimum owner / supporting role
Commercial Lead做economic / operational review；Legal counsel負責法律解釋、可執行性與legal advice；specialists按需；Project Lead整合。
## Inputs
3.1 term tracker、draft agreement / schedules、2.6 DD、client policies、counsel protocol。
## Activities
document inventory → clause map → commercial intent test → issue prioritisation → counsel questions → negotiation agenda。
## Outputs
`CONTRACT_REVIEW_PLAYBOOK.md/.docx`、`Commercial_Legal_Issue_Tracker.xlsx`、`MODEL_README.md`。
## Dependencies
輸出直接成為3.3 agenda；resolved text / positions持續餵3.4 / 3.5。
## Known
Optimum不取代律師；commercial review可以說明cost / operational / risk effect，但不可提供法律結論。
## Hypotheses
以event→allocation→measurement→remedy→cap/security→termination檢查，可較快發現交易與文字落差。
## TBD with client
counsel / privilege protocol、review scope、governing law、signing entity、approval route、issue priority與risk acceptor。
## Key risks
版本錯誤；redline未映射；把commercial偏好當法律要求；privilege / confidentiality處理錯誤；issue無owner；schedule與main body衝突。
## MVP sequence
document index + top 10 clause map → client/counsel triage → detailed tracker → negotiation agenda → review updated draft。
## Definition of Done
每項issue有document / clause、current text summary、commercial effect、legal question、priority、target / fallback、owner、status與next step；版本與counsel boundary清楚。

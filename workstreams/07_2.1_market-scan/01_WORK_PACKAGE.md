# 2.1 市場掃描與供應商盤點 — Work Package

## Purpose

建立可追溯、可比較、可逐步擴張的台灣再生能源供應市場地圖，讓 AMAT 在揭露身份或承諾採購前，先知道應驗證哪些供應類型、參與者與供應風險。

## Client question

市場上有哪些可能的供應路徑與參與者，哪些值得進入 2.2 初步接觸？

## Intended decision

G5：核准 market scan 範圍、screening criteria、研究缺口、優先接觸類別與 disclosure level。

## Client audience

Procurement、Sustainability / RE100 owner、Facilities / site energy、Finance、Legal、regional / global procurement 與 decision body；實際名單為 `TBD WITH CLIENT`。

## Optimum owner / supporting role

Market / Commercial Lead accountable；Analyst 蒐證與維護 landscape；Project Lead review judgement；Legal / policy specialist 按需要支援。

## Inputs

1.5 approved / conditional portfolio direction、1.6 G5 authority、公開官方來源、供應商公開資訊、已核准的 research question 與 information boundary。

## Activities

定義 universe → 分類 supplier / developer / retailer / project → 逐欄蒐證 → source grading → hard-screen → weighted prioritisation → small-universe review → 核准 2.2 contact list。

## Outputs

`MARKET_SCAN_METHODOLOGY.md/.docx`、`Market_Landscape.xlsx`、`MODEL_README.md`；workbook 同時提供 research protocol、source log、synthetic screening demo 與 preliminary summary。

## Dependencies

承接 1.5 scenario / constraints 與 1.6 disclosure authority；輸出直接餵入 2.2 outreach、2.3 / 2.4 assessments、2.5 bidder list / fields 與 2.6 evaluation universe。

## Known

- Optimum 以 buyer-side / client-side advisor 角色參與市場。
- 未取得 client authority 前，可先做 public desktop scan，不可自行揭露 AMAT-specific need。
- 可比較性要求穩定的 entity / project ID、as-of date、source、truth status 與 evidence grade。

## Hypotheses

- 分層檢視 retailer、developer / generator、project / asset、certificate / service interfaces 比單一 supplier list 更能暴露執行依賴。
- 初輪 shortlist 應先排除 evidence 缺失或 hard constraint 不符，而非由關係熟悉度排序。

## TBD with client

可揭露身份／site／volume／timing 的層級、approved criteria / weights、是否有 preferred / excluded counterparties、conflict rules、contact owner、regional vendor requirements。

## Key risks

過時資訊被當現況；把 supplier statement 當已驗證事實；同一專案重複計入；公開掃描過早變成市場承諾；以分數掩蓋 evidence gap。

## MVP sequence

1. 先建 8–15 個匿名／類別層級 universe 與 10 個 comparable fields。
2. Project Lead review 分類、hard screen 與 source quality。
3. 補最具決策影響的缺口，形成 priority tier。
4. G5 核准後才把小範圍名單送入 2.2；review 後再 expand。

## Definition of Done

每一列有 stable ID、category、evidence / source date、truth status、unknown、next verification；screening logic 可重算；公開事實、supplier claim、Optimum inference 與 client decision 分離；G5 可決定 contact / defer / research more。

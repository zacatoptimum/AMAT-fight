# Signing Readiness Checklist v0.1

> `PRE-SIGNING STRUCTURE DRAFT`。實際documents、signers、conditions、dates與implementation要求皆為 `TBD WITH CLIENT`。Legal sufficiency / signing authority由client Legal確認。

## G10 decision

`SIGN`、`SIGN WITH CONTROLLED CONDITIONS`、`DO NOT SIGN`。另做 `GO-LIVE READY / NOT READY`；簽署不自動等於開始交付。

## 1. Document and authority

- final agreement / schedules / guarantee / annex / addenda列表完整且版本一致；
- accepted commercial terms與G9 decision一致；
- no unresolved side letter / email commitment；
- counsel完成所需legal review；
- signing entities、names、titles、authority evidence、signature method與date確認；
- approvals / quorum / funding / budget / accounting actions有證據。

## 2. Conditions precedent / obligations

每項CP記 contract reference、responsible party、due / longstop、required evidence、dependency、status、waiver authority與consequence。區分 pre-signing、post-signing pre-COD、ongoing covenant；未完成不得只寫「to follow」。

## 3. Responsibility matrix

至少覆蓋contract owner、supplier manager、site / facilities、wheeling / utility interface、meter / data、T-REC registry / claim、invoice / settlement、forecast / reconciliation、risk / legal escalation、executive sponsor。每項有 primary / backup / contact / SLA / evidence location。

## 4. Operational readiness

- site / meter master與delivery points validated；
- wheeling / network application、agreements、milestones與contacts；
- supplier onboarding / vendor / PO / payment / tax setup；
- data transfer、formats、frequency、access、security、retention與test file；
- generation / load / delivery / certificate reconciliation rule；
- certificate account / transfer / retirement / replacement流程；
- invoice / settlement dry run與dispute route；
- incident / escalation / business continuity；
- implementation schedule、cutover、fallback與first reporting date。

## 5. Transition package to 3.6

Signed document index、commercial baseline、milestones、CP / obligations、contacts / escalation、expected delivery profile、certificate schedule、reporting / reconciliation definitions、open exceptions、risk acceptances與first 90-day governance。

## Preliminary judgement

`HYPOTHESIS`：只有document / authority、CP、operational interfaces與BAU ownership四類都通過或有explicit authorized condition時才簽；任何critical owner / evidence缺失應維持`DO NOT SIGN / NOT GO-LIVE READY`。

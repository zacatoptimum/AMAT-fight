# 3.5 簽約與執行準備 — Work Package

## Purpose
在簽署前確認final documents、authority、conditions precedent、funding、operational / data / wheeling / certificate readiness與transition owner。
## Client question
現在是否可以簽、可以開始執行；若不行，缺什麼、誰何時關閉？
## Intended decision
G10：sign / sign with controlled conditions / do not sign；核准CP與implementation transition。
## Client audience
Authorized signers、Legal、Procurement、Finance、Sustainability、Facilities / operations、IT / data、supplier。
## Optimum owner / supporting role
Readiness Lead / PMO owner；client Legal controls final documents / signature；functional owners close workstreams；Project Lead verifies integrated readiness。
## Inputs
G9 decision、final documents / redlines、CP list、approvals / funding、supplier implementation plan、site / meter / certificate requirements。
## Activities
document / authority check → CP plan → responsibility matrix → system / data / wheeling / certificate readiness → dry run → sign decision → handoff。
## Outputs
`SIGNING_READINESS_CHECKLIST.md/.docx`、`Conditions_Precedent_Tracker.xlsx`、`MODEL_README.md`、transition / responsibility matrix。
## Dependencies
簽署後直接餵3.6 baseline；未完成項目轉成controlled post-signing obligation而非消失。
## Known
Optimum不批准legal sufficiency；只有authorized client signer可簽；signature與go-live可能是不同gates。
## Hypotheses
single integrated readiness review能避免legal-ready但operational-not-ready。
## TBD with client
signer / authority evidence、CP / post-CP distinction、funding / guarantee、systems / data、wheeling / certificate contacts、cutover date、document repository。
## Key risks
錯版本簽署、authority不足、CP無證據、post-signing obligation無owner、meter / data / certificate setup落後、supplier contact不清、premature go-live。
## MVP sequence
readiness checklist → functional owner review → one dry run → G10 exception list → sign / no-sign → 3.6 handoff。
## Definition of Done
final set hash / version、approvals、signer、CP、responsibilities、data / system / wheeling / certificate、contacts / escalation、BAU owner與open exceptions都有evidence；sign與go-live分開決定。

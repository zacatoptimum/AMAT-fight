# 1.1 專案啟動與工作方式確認 — Work Package

## Purpose

在 kickoff 前把專案目標、交付使用情境、決策權、工作節奏與初期未知事項整理成可由 AMAT 驗證的 operating system；不是把尚未確認的 scope 當成既定事實。

## Client question

「我們要共同完成哪些決策、誰在何時參與、成果如何被使用，以及遇到資料或方向不確定時如何快速校準？」

## Intended decision

批准 project charter v1、初步 scope / out-of-scope、governance、working cadence、decision / escalation route、前四週工作計畫與 1.2–1.3 啟動條件。

## Client audience

HYPOTHESIS：Taiwan sustainability / RE100 owner、Taiwan Procurement、Facilities / site energy owners、Finance、Legal、regional / global sustainability、regional / global procurement、executive sponsor；正式名單 TBD WITH CLIENT。

## Optimum owner / supporting role

Owner：Project Lead / Taiwan Lead。Supporting：PMO、market / procurement analyst、model owner。Client roles 與 Zac / Founder 實際投入比例 TBD。

## Inputs

- KNOWN：本案預計涵蓋台灣企業再生能源採購顧問 delivery system。
- HYPOTHESIS：需要跨 sustainability、procurement、facility、finance、legal 與 global / regional governance。
- TBD WITH CLIENT：成功定義、business deadline、site / entity boundary、decision authority、budget process、procurement rules、legal / InfoSec requirements。
- Input artifacts：現有 proposal / SOW、NDA、已知 stakeholder names、target / policy excerpts、關鍵 milestone；尚未取得者進 client question log。

## Activities

1. 先以 expectation-validation questions 訪談 sponsor。
2. 對齊 objective、intended decisions、deliverable users 與 scope boundary。
3. 確認 RACI、meeting cadence、review SLA、decision gate 與 escalation route。
4. 建立 RAID、source、deliverable、schedule 與 change-control discipline。
5. 啟動 1.2 data request 與 1.3 workshop participant design。

## Outputs

- `PROJECT_CHARTER_AND_WAYS_OF_WORKING.md/.docx`
- `KICKOFF_DECK_CONTENT.md`
- `Kickoff_Deck.pptx`
- shared `Project_Control_Register.xlsx` 中已可用的 RAID / decision / deliverable / schedule schema

## Dependencies

依賴 client sponsor 可用性、proposal / SOW 邊界與 confidentiality / tool rules。輸出直接啟動 1.2、1.3，並設定 1.4–3.6 的 review / approval 方法。

## Known

- 專案需避免把 pre-contract hypotheses 當 AMAT facts。
- delivery 採 Define → MVP → Review → Correct → Expand。
- 18 個 workstreams 全部在方法範圍內；商務合約 scope 是否一致仍需核對 SOW。

## Hypotheses

- G0 kickoff gate 需要一位 client sponsor 可核准 governance 與 scope interpretation。
- 每個關鍵 deliverable 應有 business owner、decision date 與 intended use。
- Biweekly working review + monthly steering review 是合理 starting cadence，但須由 client 驗證。

## TBD with client

專案成功指標、named stakeholders、approval thresholds、會議頻率、跨時區限制、資料交換位置、外部市場接觸授權、報告語言、legal counsel role、change-control authority。

## Key risks

- Kickoff 只講 scope、不確認成果怎麼被使用。
- 沒有 decision owner，導致分析完成但無法定案。
- 會議太多而無 gate，或太少而晚發現方向錯誤。
- proposal 與 client expectation 不一致，未早期留下 assumption / change record。

## MVP sequence

1. MVP-0：以本包的 charter draft + 8-slide kickoff deck 做內部 red-team。
2. MVP-1：kickoff 前 30–45 分鐘 sponsor expectation-validation call；將答案寫入 client question / assumption log。
3. Review：kickoff 當場確認 decisions、owners、cadence、next-two-week actions。
4. Correct / Expand：48 小時內發出 charter v1、decision record 與 data / workshop launch pack。

## Definition of Done

- 目標、intended decisions、audience、scope / out-of-scope、RACI、cadence、decision / escalation 與 review SLA 已經 client 確認或明確標成 open。
- Kickoff deck 具結論式 title、每頁有 discussion / decision prompt，頁數在 soft target 內。
- Initial questions 全部帶 why it matters、owner、needed-by date。
- 1.2 / 1.3 owner、first MVP 與 review dates 可排程。
- 產出已通過內容、cross-handoff、confidentiality 與 render QA。

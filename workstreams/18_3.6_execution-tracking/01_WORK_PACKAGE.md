# 3.6 採購方案落地與執行追蹤 — Work Package

## Purpose
把signed arrangement轉成可監控的delivery、certificate、settlement、issue / change與BAU governance。
## Client question
是否按約交付、claims / certificates可用、商業結算正確、偏差如何處理並何時轉BAU？
## Intended decision
G11：accept transition to BAU / extend project governance；定期決定corrective action、claim / settlement、change與escalation。
## Client audience
Contract / supplier manager、Sustainability / reporting、Facilities、Finance / AP、Legal / risk、Procurement、executive sponsor。
## Optimum owner / supporting role
Implementation Lead / PMO owner至transition；functional owners operate；supplier provides evidence；Project Lead reviews material issues；BAU owner accepts handoff。
## Inputs
signed documents、3.5 transition package、expected profile / price / certificate schedule、contacts、data feeds、CP / obligations。
## Activities
baseline → milestones → delivery / certificate / invoice reconciliation → issue / change → periodic report → acceptance → BAU transfer。
## Outputs
`EXECUTION_GOVERNANCE.md/.docx`、`Implementation_Tracker.xlsx`、`MODEL_README.md`，含periodic reporting與BAU acceptance。
## Dependencies
持續回饋future procurement / supplier performance；scope change走shared change log。
## Known
Signed terms是baseline；actual delivery / certificate / settlement需逐期evidence；project closure不等於未解claims消失。
## Hypotheses
單一reconciliation key（site / meter / period / offer / certificate batch）可減少跨team錯配。
## TBD with client
data availability / cadence、systems、tolerance、certificate / reporting owner、invoice process、SLA、escalation / materiality、BAU acceptance date。
## Key risks
expected / actual定義不一致、data late、certificate mismatch、invoice差異、change未授權、issue aging、BAU owner未接受。
## MVP sequence
一個period synthetic dry run → owner review → first live month → exception-driven reporting → 90-day review → G11。
## Definition of Done
milestones、delivery、certificate、invoice / commercial issue、actions / changes / risks、reporting與BAU acceptance都可追溯；所有差異有owner / date / remedy / contractual reference。

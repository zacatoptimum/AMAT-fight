# 2.6 方案評估、盡職調查與候選名單 — Work Package

## Purpose
以預先核准、可稽核的方法，將 supplier responses、commercial normalization 與 DD evidence轉成 shortlist recommendation。
## Client question
哪些方案值得進入 negotiation，主要 value、risk、conditions與未解問題是什麼？
## Intended decision
G7 shortlist；為每個候選方案核准 conditions、DD actions、fallback與3.1 alignment topics。
## Client audience
Decision body、Procurement、Finance、Legal、Sustainability、Facilities、regional / global approvers。
## Optimum owner / supporting role
Evaluation Lead owner；commercial / market analysts；legal / financial / technical specialists；Project Lead recommendation QC；client decision body decides。
## Inputs
2.5 submissions / addenda、2.1–2.4 evidence、approved criteria / weights / hard screens、DD material、conflict declarations。
## Activities
completeness → normalization → independent scoring → calibration → DD → risk / condition mapping → sensitivity → decision memo。
## Outputs
`EVALUATION_AND_DECISION_MEMO.md/.docx`、`Scorecard.xlsx`、`MODEL_README.md`，含 DD checklist與shortlist logic。
## Dependencies
輸出直接餵 3.1 final requirements / mandate與3.2 issue list。
## Known
Hard-screen failure不能靠總分抵銷；score必須有comment / evidence；commercial normalization不可改寫supplier原始response。
## Hypotheses
recommendation應分開 intrinsic option value、evidence confidence與condition-to-proceed。
## TBD with client
criteria / weights、quorum、conflict treatment、DD depth、risk acceptance、shortlist size、decision authority與records retention。
## Key risks
confirmation bias、評分者不一致、missing data當零、價格 normalization錯誤、DD範圍不清、法律／技術意見混淆、未記錄 dissent。
## MVP sequence
一個 demo offer dry-run → rubric calibration → 2–3 offer scoring → DD red flags → Project Lead client-style review → shortlist decision。
## Definition of Done
source response、normalization、score、evidence、red flag、condition與decision traceable；未解issue有owner / date；memo清楚說明recommendation / downside / fallback。
